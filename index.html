AWS · FULL STACK01

        

          
        

        
MEDICAREPLUS

        
Hospital appointment booking — browse doctors, check availability, book a slot. PHP and MySQL, deployed on a segmented AWS network rather than a single public box.

        
LOGIC Traffic lands on an Application Load Balancer in the public subnet, which fans out to an EC2 Auto Scaling group serving PHP. MySQL runs on RDS inside a private subnet with no internet route, reachable only from the app tier's security group — and doctor images go to S3 instead of the instance disk. CloudWatch collects metrics; SNS fans alerts out to the owner.

        
  • PHP
  • MySQL
  • EC2
  • RDS
  • VPC
  • ALB
  • S3
  • CloudWatch

AWS · THREE-TIER02

        

          
        

        
QUICKLOAN

        
A loan management platform deployed as a three-tier build — separate jump, web and database servers instead of one box doing everything.

        
LOGIC A jump server in the public subnet is the only SSH entry point; web servers sit behind an Application Load Balancer and an Auto Scaling group, and RDS MySQL stays in a private subnet with no route to the internet. A NAT Gateway gives the private tier outbound access for updates, while CloudWatch and SNS cover metrics and alerting.

        
  • PHP
  • S3
  • EC2
  • RDS
  • ALB
  • NAT Gateway
  • SNS

SERVERLESS · AWS03

        

          
        

        
AWS TICKET BOOKING

        
Event listing, seat availability and ticket booking — a classic load-balanced app tier with a serverless path where the load is spiky.

        
LOGIC Public subnets hold the ALB, the NAT Gateway and the Auto Scaling group; private subnets hold the application servers and RDS MySQL, which is deployed with no public access at all. S3 keeps object storage and event processing separate from the app tier — Lambda handles the work that shouldn't block a request — and CloudWatch with SNS covers monitoring and notifications.

        
  • PHP
  • MySQL
  • Lambda
  • ALB
  • Auto Scaling
  • S3
  • SNS
  • CloudWatch

SERVERLESS · AWS04

        

          
        

        
SMARTBUILD

        
A building management dashboard for residents, complaints, maintenance and security — built serverless end to end, so there is no server to patch.

        
LOGIC The frontend is static on S3. API Gateway routes REST calls into Lambda handlers that read and write DynamoDB, which keeps the data store managed and the scaling automatic. CloudWatch covers application activity, CloudTrail keeps the AWS audit trail, and SNS carries alerts — with the data model left ready for sensor and IoT feeds.

        
  • Lambda
  • API Gateway
  • DynamoDB
  • S3
  • CloudWatch
  • CloudTrail
  • SNS

DEVOPS · DOCKER05

        

          
        

        
MULTI-NODE CI/CD

        
Three Ubuntu servers doing one job each — push, schedule, build — so a compile never lands on the Jenkins controller.

        
LOGIC The dev server prepares the app and its Dockerfile and pushes to GitHub. A webhook starts the job on the Jenkins master, which delegates execution to slave-1 over the JNLP agent protocol. Slave-1 pulls the commit, builds the image and runs the container, keeping build load and credentials off the controller.

        
  • Jenkins
  • Docker
  • GitHub
  • Webhooks
  • Ubuntu

CI/CD · NGINX06

        

          
        

        
JENKINSFLOW

        
A pipeline that replaces the manual step nobody enjoys: SSH in, copy files, reload the server.

        
LOGIC Three stages run in order — checkout, validate, deploy — and the build is written straight into /var/www/jenkins-site, which Nginx serves on port 80. A GitHub webhook kicks the job off on push once the trigger is verified; until then it runs from the Jenkins UI with the same result.

  • Ubuntu

AUTOMATION · LINUX07

        

          
        

        
ANSIBLE ROLE

        
Adding a fourth web server should be one line of inventory, not an afternoon of SSH — so the setup lives in a role.

        
LOGIC The control node reaches managed hosts over SSH and applies the webserver role: install the package, drop the config, copy files/index.html, enable and start the service, then notify a handler to reload only when something actually changed. Tasks, handlers, files and vars stay separated, so the playbook is reusable across environments.

        
  • Ansible
  • Playbooks
  • Roles
  • YAML
  • SSH

AUTO-HEALING NGINX

        
Recovery that does not wait for a human to read an alert at 3am — a timer checks the service and puts it back.

        
LOGIC A Bash script asks systemd whether nginx is active; if not it restarts the unit, re-checks, and appends the outcome to /var/log/auto-heal-nginx.log. A systemd service plus timer runs it on a schedule on each node, and Ansible ad-hoc commands push the script and verify state across the fleet without a full playbook.
